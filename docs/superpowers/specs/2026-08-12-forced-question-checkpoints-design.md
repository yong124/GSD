# 강제 질문 체크포인트 및 답변별 결과 설계

## 목적

현재 질문 시스템은 조사 수첩의 선택 탭에만 있어 플레이어가 존재와 사용 시점을 알기 어렵다. 그러나 질문 해결 상태와 해결 개수는 후반 폭로 선택지, 조건부 대사, 엔딩 분기에 사용된다. 질문을 선택형 부가 메뉴가 아니라 시나리오가 지정한 시점에 반드시 마주치는 추리 단계로 바꾼다.

이 변경의 목표는 다음과 같다.

- 조사와 단서 획득 뒤에 질문 UI가 강제로 열린다.
- 한 체크포인트에는 장면에 따라 질문 하나 또는 여러 개를 배치할 수 있다.
- 답변 선택지마다 정답 여부, 침식·평판 변화, 반응 대사와 후속 분기를 다르게 지정한다.
- 오답도 서사를 진행시키며, 선택한 오답의 성격이 이후 상태와 장면에 남는다.
- 침식이 10에 도달하거나 평판이 0에 도달하면 기존 게임오버 장면으로 연결한다.

## 플레이 흐름

기본 흐름은 다음과 같다.

```text
장면 진행
→ 조사 선택
→ 단서 획득
→ 지정된 질문 체크포인트 진입
→ 답변 선택
→ 정답 또는 오답 결과 표시
→ 답변별 효과 적용
→ 게임오버 한계 확인
→ 답변별 후속 대사·장면 또는 다음 질문
```

질문 UI는 대사와 일반 선택 입력을 막는 전용 진행 화면으로 연다. 플레이어가 닫기 버튼이나 수첩 키로 건너뛸 수 없으며, 저장 데이터를 다시 불러와도 완료하지 않은 체크포인트가 유지된다.

## 체크포인트 유형

씬마다 질문 체크포인트를 선택적으로 지정한다.

- `All`: 지정된 질문을 순서대로 모두 답해야 체크포인트가 끝난다.
- `Any`: 지정된 질문 중 하나를 골라 답하면 체크포인트가 끝난다.

질문 하나만 지정한 경우에도 같은 구조를 사용한다. 별도의 단일 질문 전용 런타임 분기는 만들지 않는다.

체크포인트는 해당 장면의 대사 또는 조사가 끝나 다음 진행으로 넘어가려는 순간 전환을 가로채서 열린다. 질문 결과에 별도 후속 장면이 없으면 원래 예정된 전환을 재개한다. 답변에 후속 장면이 지정되어 있으면 그 장면으로 이동하고 원래 전환은 폐기한다.

체크포인트 완료 여부는 저장 가능한 상태로 기록한다. 이미 완료한 체크포인트는 재진입 시 다시 열리지 않는다. 이미 해결된 질문은 목록에서 완료 상태로 처리하며 중복 보상을 지급하지 않는다.

## 답변 모델

답변은 단서 하나를 임의 제출하는 방식이 아니라 저작된 가설 선택지로 제공한다. 각 답변은 문장과 그 답변을 뒷받침하는 단서 목록을 가진다. 이 방식은 복수 단서 조합 정답을 유지하면서 오답마다 고유한 의미와 결과를 부여한다.

예시:

- `교단이 푸른 천과 쪽지를 표식으로 이판규를 호출했다.`
  - 요구 단서: 푸른 천, 붉은 쪽지
  - 정답
- `이판규가 환각 속에서 표식을 스스로 만들어 냈다.`
  - 요구 단서: 붉은 쪽지
  - 오답, 침식 증가
- `이판규가 관심을 끌기 위해 사건을 꾸몄다.`
  - 요구 단서 없음
  - 오답, 평판 감소

보유하지 않은 필수 단서가 있는 답변은 선택할 수 없게 표시한다. 모든 답변이 잠기는 체크포인트는 저작 오류로 취급한다. validator는 질문마다 최소 두 개의 답변, 최소 한 개의 정답, `RequiredEvidenceIDs`가 비어 있어 항상 고를 수 있는 답변이 최소 하나 있는지 검사한다. 정답 단서의 실제 경로 보장은 브라우저 QA로 확인한다.

## 답변 결과와 게이지

각 답변은 기존 `EffectTable`의 효과 그룹을 참조한다.

- 초자연적 현상에 홀린 오답: 침식 증가
- 근거 없는 단정이나 증언자 압박: 평판 감소
- 특히 위험한 오답: 침식 증가와 평판 감소를 함께 적용 가능
- 정답: 질문 해결 상태, 해결 질문 수, 질문 자체 보상을 한 번만 적용

침식은 높을수록 위험하므로 오답 효과는 양수 증가로 기록한다. 평판은 낮을수록 위험하므로 오답 효과는 음수 감소로 기록한다.

효과를 적용한 직후 한계를 검사한다.

- `Erosion >= 10`: 결과 피드백을 보여준 뒤 `scene_gameover_erosion`으로 이동
- `Credibility <= 0`: 결과 피드백을 보여준 뒤 `scene_gameover_credibility`로 이동
- 두 한계가 동시에 충족되면 침식 게임오버를 우선한다.

오답은 질문 해결 상태를 만들지 않지만 해당 체크포인트에서 그 질문에 답한 사실은 기록한다. 따라서 오답 분기가 진행된 뒤 같은 체크포인트가 반복해서 열리지 않는다.

## 데이터 구조

### QuestionTable

질문 자체의 정의를 유지한다.

- 질문 ID, 제목, 설명
- 공개 조건과 상태 문구
- 해결 상태 ID
- 정답 보상
- 관련 단서

기존 `SolutionEvidenceIDs`와 `SolutionMode`는 마이그레이션 입력으로 사용한 뒤 답변 판정의 소스 오브 트루스에서 제외한다. 실제 정답 여부는 `QuestionAnswerTable.IsCorrect`가 담당한다.

### QuestionAnswerTable 신규

한 행이 하나의 저작된 답변 선택지를 나타낸다.

| 필드 | 의미 |
|---|---|
| `AnswerID` | 답변 고유 ID |
| `QuestionID` | 소속 질문 ID |
| `SortOrder` | 표시 순서 |
| `AnswerText` | 플레이어에게 보일 가설 문장 |
| `RequiredEvidenceIDs` | 답변을 선택하기 위해 필요한 단서 목록 |
| `IsCorrect` | 정답 여부 |
| `EffectGroupID` | 침식·평판 등 상태 변화 |
| `ResultText` | 선택 직후 결과 설명 |
| `NextType` | `Resume`, `Dialog`, `Scene` |
| `NextID` | 후속 대사 또는 장면 ID |

런타임 top-level 키는 `question_answers`, 분리 파일은 `game/data/tables/question_answers.json`으로 한다.

### SceneTable 확장

질문을 강제로 여는 장면에만 다음 필드를 사용한다.

| 필드 | 의미 |
|---|---|
| `ForcedQuestionIDs` | 순서가 있는 질문 ID 목록 |
| `QuestionMode` | `All` 또는 `Any` |

체크포인트는 장면의 대사와 조사·선택 처리가 끝나 장면을 이탈하기 직전에 열린다. 완료하면 질문 진입 전에 보류한 원래 전환을 재개한다. 초기 구현에서는 대사 중간 인덱스 삽입이나 트리거 종류 설정을 만들지 않는다. 실제로 두 번째 트리거 위치가 필요해질 때 필드를 추가한다.

### 저장 상태

- `QuestionSolved_<QuestionID>`: 정답으로 해결했는지
- `QuestionCheckpointCompleted_<SceneID>`: 해당 씬의 강제 질문 단계가 끝났는지
- `QuestionAnswered_<SceneID>_<QuestionID>`: 해당 체크포인트에서 질문에 답했는지
- `SolvedQuestionCount`: 정답 해결 개수

## 기존 수첩 질문 탭

수첩의 질문 탭은 삭제하지 않고 읽기 전용 기록 화면으로 바꾼다.

- 공개된 질문과 현재 상태를 확인한다.
- 해결한 질문은 결론과 사용한 답변·단서를 보여준다.
- 실패한 질문은 당시 선택한 추론과 결과를 보여준다.
- 수첩에서는 답을 제출하거나 질문을 해결할 수 없다.

이렇게 해야 플레이어가 체크포인트를 우회해 후반 조건을 임의로 해금할 수 없다.

## 기존 콘텐츠 이관 원칙

현재 10개 질문은 모두 유지한다. 각 질문에는 최소 정답 하나, 침식형 오답 하나, 평판형 오답 하나를 저작한다. 서사적으로 두 위험이 동시에 발생하는 답변에는 침식 증가와 평판 감소를 함께 적용할 수 있다.

초기 체크포인트 배치는 다음과 같이 확정한다.

| 체크포인트 장면 | 모드 | 질문 |
|---|---|---|
| `ch2_factory_shock` | `All` | `QIpangyuCall` |
| `ch2_well` | `All` | `QIpangyuMadness`, `QCallPattern` |
| `ch3_room4_conclusion` | `All` | `QSonggeumMissing`, `QSonggeumRunaway`, `QRoom4Purpose` |
| `ch4a_slum` | `All` | `QArchivePattern` |
| `ch5_ritual_room` | `All` | `QRitualLead`, `QRitualAccident`, `QRitualErasure` |

단일 질문과 복수 질문을 같은 시스템으로 처리하되, 현재 시나리오의 핵심 질문은 모두 답해야 하므로 초기 콘텐츠는 `All`을 사용한다. `Any`는 이후 한 장면에서 여러 추론 중 하나만 선택하게 하는 보조 질문 체크포인트에 사용할 수 있도록 스키마와 런타임에서 지원한다.

질문은 해당 체크포인트 장면에 진입한 시점부터 수첩에 공개한다. 시작부터 공개 조건이 없는 기존 네 질문도 위 체크포인트에 맞춰 공개 조건을 부여한다. 각 체크포인트에서는 표에 적힌 질문과 연결된 답변만 표시한다.

현재 단서 지급 기준으로 `ch2_factory`까지 푸른 천과 붉은 쪽지, `ch3_room4_conclusion`까지 일기장·푸른 한복·가면, `ch4a_slum`까지 과거 기사·빈민가 증언, `ch5_ritual_room`까지 의식 악보·의례 기록이 확보된다. 답변의 필수 단서는 이 시점별 보유 범위 안에서만 지정한다. 선택 경로 때문에 정답과 모든 오답이 잠기는 배치는 허용하지 않는다.

질문 해결을 참조하는 기존 조건부 대사와 최종 `CG_Proof_All` 구조는 유지한다.

## 런타임 책임 분리

- `scene.js`: 체크포인트 진입 시점 감지, 보류된 전환 저장, 완료 후 전환 재개
- `evidence.js`: 단서 수집, 질문·답변 데이터 준비, 정답 처리, 체크포인트 진행, 답변 기록
- `ui.js`: 강제 질문 화면 렌더링과 입력 잠금
- `state.js`: 체크포인트·답변·질문 해결 상태 저장
- `choice.js`: 일반 조사 선택 흐름은 유지하고 장면 전환 전에 체크포인트 훅만 호출

기존 질문 조회·해결 로직이 이미 `evidence.js`에 있으므로 별도 모듈을 만들지 않는다. 질문 코드가 실제로 독립 변경이 어려울 정도로 커질 때만 분리한다.

## 에디터와 파이프라인

스키마 변경은 다음 계층을 같은 작업에서 맞춘다.

- `game/data/game_data.js`
- `game/data/tables/questions.json`
- `game/data/tables/question_answers.json`
- `game/data/tables/scenes.json`
- EditorNode 질문·답변 편집 UI와 저장
- `split_game_data.py`
- `export_to_json.py`
- `json_to_generated_xlsx.py`
- `validate_game_data.py`
- generated XLSX의 `QuestionAnswerTable`

질문과 답변 문구, 효과, 분기 ID는 런타임 JS 상수로 작성하지 않는다.

## 오류 처리

- 질문 ID나 답변 ID가 없으면 진행을 조용히 건너뛰지 않고 콘솔 오류와 플레이어용 오류 메시지를 표시한다.
- 표시 가능한 답변이 하나도 없으면 진행을 막고 저작 오류로 보고한다.
- 존재하지 않는 효과·대사·씬 참조는 validator 오류로 처리한다.
- 이미 해결된 질문에 정답을 다시 적용해도 보상과 해결 개수는 증가하지 않는다.
- 저장·불러오기 후 완료한 체크포인트와 선택한 답변 결과가 동일하게 복원되어야 한다.

## 검증 기준

정적 검증:

- 모든 체크포인트의 질문 ID가 존재한다.
- 모든 답변의 질문·단서·효과·후속 ID가 존재한다.
- 질문마다 답변이 둘 이상이고 정답이 하나 이상이다.
- `QuestionMode`, `NextType` 값이 허용 목록에 속한다.
- `game_data.js`와 분리 tables의 구조가 일치한다.
- 런타임과 EditorNode JS 구문 검사가 통과한다.

브라우저 검증:

- 단일 질문 체크포인트가 자동으로 열리고 닫아서 우회할 수 없다.
- `All` 체크포인트는 모든 질문을 처리한 뒤 진행한다.
- `Any` 체크포인트는 하나의 질문 결과 후 진행한다.
- 정답은 해결 상태와 보상을 한 번만 적용한다.
- 오답별로 침식·평판·후속 대사가 다르게 적용된다.
- 침식 10과 평판 0에서 각각 결과 피드백 뒤 게임오버로 이동한다.
- 저장·불러오기 후 질문이 중복 실행되지 않는다.
- 수첩 질문 탭에서 답을 제출해 체크포인트를 우회할 수 없다.
- 최종 폭로 선택지는 인물·구조·의식 질문 조건을 만족했을 때만 열린다.

## 범위 제외

- 제한 시간 답변
- 무작위 질문 또는 답변 순서
- 대사 한 줄 중간에 질문을 삽입하는 범용 타임라인 시스템
- 질문 전용 신규 체력 게이지
- 기존 엔딩 종류 추가
